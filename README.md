# 错题元数据系统 · Android

英语填空题的字段库。收录判据只有一条：**一个句子、句中至少一个空**。

它要答的是「**这一类空该填成什么形态**」，不是「你错得怎么样」——
错误率、加权失分、成熟度门槛这类统计在 v3 被整层删掉了，它们答的是后一个问题。

Kotlin + Jetpack Compose + Room，单人使用，minSdk 26，没有服务端。

## 一条线

数据分四级，**后一级的输入永远是前一级的输出**：

```
照片 ──识别──→ 候选题 ──逐条标 错/蒙对──→ 原始数据（题干 + 答案）
                                              │
                                            分析（每题一条：板块 · 答案形式 · 判断依据）
                                              │
                            小方向（一个板块一棵考点树）──→ 大方向（全局一棵）
```

小方向读的是这一支下所有题的分析；大方向**只读各小方向的输出**，绝不回头看原题——
否则两级会各自从原始数据重算，「上一级的输出是下一级的输入」就成了一句空话。

递归总结能收敛，靠的是压缩而不是模型自觉：送进模型的体积随**形态种类数**增长，
不随题数增长。47 题三种形态是十几行，300 题十二种形态还是十几行。

## 界面

底部三个板块，顶栏两个图标。

| 页面 | 干什么 |
|---|---|
| **录入** | 拍照或选图识别 → 确认页逐题标 错 / 蒙对 → 提交（可勾选录入后自动分析） |
| **原题** | 一切的来源。搜索、筛选、编辑题干与答案；长按进多选，选中的一起分析或一起删；「重复 N」筛出同一道题录了两遍的 |
| **复习** | 按板块汇总小方向，再生成大方向 |
| 设置 | 厂商与模型、端点、导出与备份、检查更新 |
| 提示词 | 六段全部可看、可改、可还原 |

**分析跑哪些由选择决定**，一条也是它三十条也是它，走同一条并发路径（4 条并发）。

## 快速开始

1. 设置页 →「厂商与模型」→ 选一个厂商 → 填 API Key。
   客户端会去问厂商这个 Key 能用哪些模型，给识别（视觉）与判断（文本）两档各挑一个。
   两档可以是不同厂商：识别天天跑挑便宜的，判断决定分析质量挑强的。
2. 录入页拍照 → 确认页逐题标记 → 提交。
3. 原题页选中要分析的题 → 分析。
4. 复习页按板块「汇总小方向」，最后「生成大方向」。

拉不到模型清单不影响使用：内置候选和手填模型 ID 都在，404 只说明这个厂商
没开放清单接口，跟 Key 对不对无关。

**联网范围**：识别、分析、两级汇总需要 API Key；原题的增删改查、已汇总的方向、
导出与备份全部离线可用。

## 目录

```
app/src/main/kotlin/com/ecs/
├── core/     纯 Kotlin，不 import 任何 android.*（硬约束）
│   ├── model/ parse/ tree/ rules/ agg/ direction/ dup/ image/ prompt/ update/ export/
├── agent/    模型调用层 + 识别 / 分析 / 汇总三个任务 + 并发闸门
├── data/     Room、DataStore、方向文件、自动备份、仓库
└── ui/       Compose 页面与单个 ViewModel
logic-tests/  独立 JVM 构建：直接编译 core/ 与 agent/ 并跑单元测试
```

## 构建与测试

```bash
./gradlew :app:assembleDebug          # 需要 Android SDK 34
./gradlew -p logic-tests test         # 248 个用例，不需要 Android SDK
```

`logic-tests` 把 `core/` 与 `agent/` 作为源目录直接编译，不是副本，改一处两边同步。

## 安装

Release 页下载 `ecs-<版本>.apk`。自 v4.1.0 起签名固定，**任意两版之间可以直接覆盖安装**，
数据不丢；发版流程会逐字比对签名指纹，不一致就发不出去。

从 v4.0.1 及更早版本升级需要先卸载（那几版用的是构建机现场随机生成的 debug 密钥，
签名互不相同），卸载会清空本地数据——先在 设置 → 导出与备份 里导出并分享出去。

自己验一份下载到的包（不需要 Android SDK）：

```bash
scripts/verify-apk-cert.sh ecs-4.3.0.apk
```

## 几条不打算改的取舍

**原题是唯一数据源。** v2 不存原题，理由是「让任何模型不接触原题也能诊断」；
v3 推翻了它——换模型重跑分析时没有原料就什么都做不了。只存题干与答案，不存选项、不存图。

**录入永不阻断。** 校验的产物是状态与提示，不是拒绝写入。唯一会真正拒绝的是 id
非法或重复，因为那会破坏主键。

**归不进板块就标未归类，不硬塞。** 汇总读的是板块里的全部分析，混进一条不属于这里的
会把整棵树带偏；留在原题页反而看得见、改得掉。

**选择题只剥不存。** 正确选项的内容进 `answer`，选项本身在识别之后即丢弃——
数据库里没有 `options` 这个字段，判断依据里也不许提到选项。

**不识别手写作答。** 识别错会连带污染判断依据和后续全部分析，而这种噪声在汇总后
完全看不出来：结论跑偏，报告依然体面。

**删除要留退路。** 批量删之前自动导一份备份，批量删过确认框，单条删要点两次。
