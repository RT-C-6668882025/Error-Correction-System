# 数据模型

## 一条记录 = 一个空

`core/model/Models.kt` 的 `ErrorRecord` 分成两半，界限是硬的：
**上半是你确认过的原始事实，下半是分析的产出**。分析可以重跑、可以换模型、
可以改提示词，原始事实一个字都不动。

### 原始数据

| 字段 | 说明 |
|---|---|
| `id` | `q_034_1` = 前缀 + 题号(3 位) + 空序。老库的 `gf_` / `wc_` 前缀仍然认得 |
| `src` | `paper` 卷名、`no` 题号、`slot` 空序、`batch` 录入批次 `b01` |
| `srcRef` | 来源引用（照片等），可空 |
| `stem` | 题干全文。一切的来源，识别错了要能改回来 |
| `given` | 括号里的提示词 / 中文提示 |
| `answer` | 正确答案。选择题剥离后写的是正确选项的内容 |
| `confidence` | `错` / `蒙对`。只录错题会漏掉蒙对的题，所以单独一档 |
| `createdAt` | 入库时间戳 |

### 分析产出

| 字段 | 说明 |
|---|---|
| `branch` | 所属板块，形如 `词法/名词`，取自骨架十九支 |
| `formShape` | 答案形式：这个空该填成什么。结合上下文推断，不是查表查来的 |
| `basis` | 判断依据：看到什么客观特征才推出上面那个形态 |
| `formContext` | 语境限定：本句独有，一次性，不参与汇总 |
| `note` | 备注 |
| `status` | `已分析` / `待补答案` / `待分析`，由字段现状推导，不由调用方指定 |

`analyzed()` = `branch` 与 `formShape` 都非空。界面上还要再分一档：

- **待分析** —— `formShape` 为空，压根没跑过；
- **未归类** —— 跑过了、形态也有，但 `branch` 落在十九支之外，复习页看不到它。

混成一个数字，人会以为分析没跑，而真相是跑了、只是没归进去——复习页一片空白
却没人知道为什么。

## 主键：uid

```
uid = "{paper}#{id}"        例：2023真题卷#q_034_1
```

`id` 只含题号与空序，**跨卷必然重复**，单靠它做主键会把不同卷的同号题覆盖掉。

## Room

表 `records`，主键 `uid`，索引 `branch` / `status` / `paper` / `batch` / `created_at`。
列名与 `ErrorRecord` 一一对应，同样分成两半。

**迁移是真迁移，不是 `fallbackToDestructiveMigration`**——后者会把已经录进去的题清空。

| 版本 | 变化 |
|---|---|
| 1 → 2 | 加 `stem` 列。旧记录为 null，在原题页显示为「没有题干，点开补」 |
| 2 → 3 | 重建表：去掉 `section` 与统计层遗留的六列；`kaodian` → `branch` 并把四层路径截到板块那一层；`form_rule` → `form_shape`；`eye` → `basis`。旧记录原样搬过去 |

批量删除走 `deleteAll(uids)`，按 900 个一批切开——SQLite 一条语句最多 999 个变量，超了直接抛。

## 判重（`core/dup/Duplicates`）

入库时按 `uid` 去重，挡得住同一份卷子重复提交；挡不住**换个卷名再拍一次**、
或**导入一份别处导出的备份**——uid 不一样，同一道题就在原题页里躺两条，
分析各跑一次，汇总时还会被当成两次证据，把某一种形态的权重顶上去。

判据是「**题干 + 空序 + 答案**」，只看原始事实，不看分析产出：
分析是可重跑的派生数据，拿它判重等于让结论决定输入。

归一只抹写法上的差别——大小写、空白、标点（含全角）、下划线长度——
**但空的位置保留**：连续下划线归一成一个 `_` 而不是抹掉，否则
`___ man playing ___ guitar` 这种一句三空会被并成一条。

同题干同空序下再按答案分簇：

- 答案不同的**不并**。那是两道不同的题，或者有一条抄错了，两种都不该由程序替人做主。
- 答案没填的并进唯一的那个答案里（多半就是它，只是还没补上）；有两个以上不同答案时
  自成一簇。

每簇留一条：**已分析的优先**（删了要重跑一次），其次有答案的，再其次录得早的，
最后按 uid 兜底——所以同一批输入每次留下的都是同一条，可以钉成测试。

它只回答「哪些重复、该留哪条」，**不删**。界面把「重复·留这条」和「重复」标在卡片上，
删除永远是人点的。

## 删除

原题是一切的来源，删掉之后它的分析、以及它在小方向里贡献的那一份都不再有依据。
所以三道闸：

1. 批量删之前**自动导一份备份**（备份目录里多一份的代价近乎为零）；
2. 批量删要过确认框，确认框里写清代价；
3. 单条删要点两次——那个按钮紧挨着「关闭」。

## 导出与备份

一份导出是一个目录，四个文件：

| 文件 | 内容 |
|---|---|
| `README.md` | 唯一的说明书，≤ 120 行，必须自洽 |
| `data.json` | 全部原题（含还没分析的——换个模型重跑时缺原料就什么都做不了） |
| `data.csv` | 同上，16 列：id, paper, no, slot, batch, stem, given, answer, confidence, created_at, branch, form_shape, basis, form_context, status, note |
| `directions.json` | 两级汇总的产物，缺了就只有原始数据 + 分析 |

硬指标：**这份包交给一个全新的模型会话，不加任何提示词，就能读懂并接着干活**。

自动备份：每新增 50 条导出一次，保留最近 5 份（`data/backup/BackupManager`）。
本地 SQLite 丢失等于全部积累归零，这一份是唯一的兜底。分享时打成 zip 写进 `cacheDir`
——那是给系统分享用的中转文件，发完就没用了，让系统自己回收。

方向另存在 `filesDir/directions.json`，按 `scope` 覆盖写：重跑某一支只换那一份，
别的板块的汇总结果不受影响——汇总一次要花模型调用，不该因为动了一支就全部作废。

设置存在 DataStore（`ecs_settings`）：端点列表、两档的端点与模型、批次号、
上次备份时的条数、复习层级、Key 是否锁定、模型清单缓存（只存 ID，能不能看图是算出来的，
存了反而会过期）。提示词覆盖值单独一个 DataStore（`ecs_prompts`）。
