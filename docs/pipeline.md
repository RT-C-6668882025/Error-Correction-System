# 流水线

一条线，四级。**后一级的输入永远是前一级的输出**——这是整个设计的主轴，
所以每一级都要能单独重跑，而重跑不影响它上游的原始事实。

```
照片 ──识别──→ 候选题 ──你逐条标记──→ 原始数据 ──分析──→ 每题一条分析
                                                              │
                                        ┌─────────────────────┘
                                        ↓
                          小方向（一个板块一棵考点树）──→ 大方向（全局一棵）
```

## 0 图片预算（`core/image/ImageBudget`）

随手拍的卷子 4–8 MB，base64 再涨三分之一，一次最多五张——请求体几十兆，
移动网络发不完，这就是「识别超时」最常见的那一种。

先按 `inSampleSize`（只在 2 的幂上生效）粗降到内存放得下，再等比缩到长边 **1600**，
压成 JPEG 质量 **82**：单张 200–400 KB，小一个数量级，而印刷体题干在这个分辨率上
没有可感知的识别损失。本来就小的图原样返回——放大不会让模型多认出一个字母。

解码策略是纯计算，在 `logic-tests` 里有用例；碰 `Bitmap` 的那一半在 `ui/util/ImageLoader`，
且都跑在 IO 线程（早先跑在 `onClick` 里，大图会先 ANR）。

## 1 识别（`agent/PaperScanner`，视觉模型）

| | |
|---|---|
| 输入 | 1–5 张压缩后的图 |
| 输出 | `Question(no, slot, stem, given, answer, confidence, isChoice, options)` |
| 提示词 | `SCAN` / `SCAN_ANSWERS` |
| max_tokens | 8000 |

收录判据只有一条：**句子 ≥ 1、句中空 ≥ 1**。不区分题型——识别出来的就是原始数据，
哪些是错题、哪些是蒙对的由你在确认页标。

**不识别手写作答**：识别错会连带污染判断依据和后续全部分析，而这种噪声在汇总之后
完全看不出来——结论跑偏，报告依然体面。

**选择题只剥不存**（`core/parse/ChoiceStripper`，本地做，可复现可单测）：
正确选项的内容写进 `answer`，选项本身在这一层之后即丢弃，数据库里没有 `options` 这个字段。
选项是同一词根的不同形态时取原形写进 `given`，词根对不上就留空——宁可空着，
也不写进一个错的原形。

## 2 确认与入库（`ui/screen/ConfirmScreen` + `data/repo/RecordRepository.add`）

逐题三态标记：不标 / 错 / 蒙对。**只有标过的才入库**，不标的既不入库也不分析。
`confidence` 低于 `IDENTIFY_CONF_FLOOR`（0.8）的在确认页标出来提醒你核对。

入库按 `uid` 去重（见 [data-model.md](data-model.md)），跳过的条数会在提示里说清楚。
勾了「录入后自动分析」就接着走第 3 步，带进度。

**录入永不阻断**：校验的产物是 `status` 与提示，不是拒绝写入。唯一会真正拒绝的
是 id 非法或重复，因为那会破坏主键。

## 3 分析（`agent/Analyzer`，文本模型）

一题一次调用，彼此不共用上下文。

| | |
|---|---|
| 输入 | 题干、括号提示词、答案、（选择题的选项，仅作判断依据）、板块清单 |
| 输出 | `branch` / `form`（答案形式）/ `basis`（判断依据）/ `context`（语境限定） |
| 提示词 | `ANALYZE`（+ 选择题时追加 `ANALYZE_CHOICE`） |
| max_tokens | 首次 3072，重试 6144 |
| temperature | 首次 0.0，重试 0.3 |

推断的是「**这个空该填成什么形态**」，不管考的是词性还是固定搭配——
它同时是一道排除题：考点是名词，答案就不可能是动词。

**最多两次尝试**，第二次会把上一次错在哪原样说回去（解析失败 / branch 不在清单里 /
依据长度越界或含禁用词），否则模型多半原样再给一遍。两次都不行才抛，且抛的是真正的原因。

**归不进板块就标未归类，不硬塞**。汇总那一步读的是板块里的全部分析，混进一条
不属于这里的会把整棵树带偏；留在原题页反而看得见、改得掉。板块匹配本身是宽容的
（见 [prompts.md](prompts.md) 里的骨架一节），真对不上才算未归类。

**跑哪些由选择决定**：原题页长按进多选，选中的一起跑，一条也是它三十条也是它，
走的是同一条并发路径（`Batch.map`，4 条并发）。

## 4 小方向（`agent/DirectionBuilder.minor`）

一个板块一次调用。输入是这一支下每道题的分析，输出是这一支的考点树。

送出去之前先过一遍**确定性压缩**（`core/agg/Compressor`）：

- 同一种答案形式归并成一个「坑」，带上支撑它的题数；
- 组内的判断依据与语境各自去重计数，每个坑只留频次最高的 3 条 / 2 条；
- 坑数超过 40 时，尾部只留形态名——覆盖不丢，体积有界。

于是送出去的体积随**形态种类数**增长，而不再随题数增长：47 题三种形态是十几行，
300 题十二种形态还是十几行。这是递归总结能收敛的前提。

三条底线：形态原文一字不改；只做字面归一（空白、全角标点、句末句号、大小写），
近义词和编辑距离一律不碰——那会真的把两个不同的坑并成一个；同一批输入永远压出
同一个结果，所以可以钉成测试。

括号里的频次只用来判断哪些形态是主线，明确要求不要写进输出。它和被砍掉的统计层
不是一回事：那一层答的是「你错得怎么样」。

## 5 大方向（`agent/DirectionBuilder.major`）

输入**只有各小方向的输出**，绝不回头看原题——否则「上一级的输出是下一级的输入」
就成了一句空话，两级会各自从原始数据重算，结论也就对不上。有一条测试专门盯着
大方向的输入负载里不含任何原题字段。

送的也不是整棵树的全文，而是每棵树的压缩视图：**骨架**（末端以上的路径，去重保序）
加**去重后的末端清单**（`考点名　形态规则`），单个板块的末端超过 `LEAF_CAP`（30）
就截断并注明「更细的留在小方向里」。这一级要判断的是「哪些板块在考同一种判断」，
细枝末节本来就该留在下一级。

末端清单带着考点名是有意的：只送规则字符串，上一级就只剩一堆无主的句子，
那才叫把考点抽象掉了。

树深上限 `Direction.MAX_DEPTH` = 5，解析时超深直接丢弃。

## 重跑的代价

| 重跑 | 影响 |
|---|---|
| 一条分析 | 只覆盖这条记录的分析产出，原始事实不动 |
| 一个板块的小方向 | 按 `scope` 覆盖写，其他板块的汇总结果不受影响 |
| 大方向 | 只读当时已有的小方向 |

所以换模型、改提示词之后，可以只重跑受影响的那一段，而不是整条链路。
