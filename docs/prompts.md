# 提示词与输出红线

模型判断得准不准，一半取决于提示词，藏起来没有道理——**六段全部可看、可改、可还原**
（顶栏提示词图标，或设置页里的入口，或原题页「改分析提示词」）。

## 拆成两半

| | 可改性 | 内容 |
|---|---|---|
| **正文** `body` | 可改 | 判断标准、语气、你自己想加的规则 |
| **契约** `contract` | 只读，自动拼在末尾 | 输出的 JSON 结构、字段硬约束、禁用词 |

这么拆是因为输出结构是解析的前提，改坏了整条链路会**静默失败**——页面照出，只是全空。
契约锁死之后，正文清空也毁不掉解析（有测试盯着这一点）。
「还原默认」删的是你的覆盖值，不是把提示词清空。

## 六个槽位

| 槽位 | 什么时候用 | 输出 |
|---|---|---|
| `ANALYZE` | 每道题一次 | `{branch, form, basis, context}` |
| `ANALYZE_CHOICE` | 分析剥离过选项的单选题时，追加在上一段之后 | 同上，另加两条约束 |
| `DIRECTION_MINOR` | 一个板块一次 | 嵌套节点数组 `[{name, rule?, children?}]` |
| `DIRECTION_MAJOR` | 全局一次 | 同上，顶层只能是 词法 / 句法 / 语法 |
| `SCAN` | 拍照识别 | 题目数组 |
| `SCAN_ANSWERS` | 识别答案页 | 题号 + 答案数组 |

改前一段会顺着往下影响后一段，这是设计如此：后一段的输入永远是前一段的输出。

## 判断依据的红线（`core/rules/Validation`）

`basis` 回答的是「**看到什么才推出这个形态**」，所以只能写看得见的东西——
位置、词形、标点、搭配、前后成分。

| 规则 | 值 |
|---|---|
| 长度 | 10–25 字 |
| 禁用词（写成了结论或解释） | 考查、需要、应该、主要、判断 |
| 禁用词（引用了不落库的东西） | 选项、排除、A项、B项、C项、D项 |
| `context` 长度 | ≤ 20 字，没有就留空 |

- 合格：`空前有 the，空后接 of 短语` / `as … as 之间，修饰的是动词`
- 不合格：`考查名词后缀转换`（这是结论）/ `因为这里要用名词`（这是解释）

选择题那组禁用词的理由：选项不落库，依据里引用选项等于引用了不存在的东西——
这条记录换个模型重跑就失效了。

校验不合格会触发一次重试，并把「上一次错在哪」原样说回去。

## 文案禁止项（`core/rules/StyleGuard`）

所有面向人的生成文本过这一道：叙事词（综上所述、值得注意的是、不难发现……）、
自我指涉（本次分析、本报告……）、空泛建议（加强学习、多加练习、注意区分……），
以及任何题号。

清洗策略是分开的：**空泛建议整句删**（删掉后结论不变），叙事词与自我指涉
**只抹掉词本身**——句子的信息量在后半句，不能连着删。

## 板块骨架（`core/tree/Skeleton`）

三个大类、十九个中类，**写死在代码里**，模型只填第三层及以下。

| 大类 | 中类 |
|---|---|
| 词法（9） | 名词、代词、形容词、副词、动词、数词、介词、连词、冠词 |
| 句法（3） | 句子成分、句子结构、句子种类 |
| 语法（7） | 主谓一致、时态、语态、主从复合句、特殊句型、虚拟语气、非谓语动词 |

写死而不是让模型每次自己分组，是因为：

1. **名字固定**。汇总跑两次不会一次叫「名词」一次叫「名词用法」，历史能对比。
2. **范围清楚**。每支带一句 `scope` 写进提示词限定模型别跑题，也告诉你这一支管什么。
3. **归属可校验**。分析输出的 `branch` 必须命中这十九支之一，对不上就是未归类。

匹配是宽容的：逐字相等太脆——模型给「词法 / 名词」「词法／名词」「　词法/名词　」
的时候它其实答对了，判成未归类是我们的问题不是它的。所以每段单独 trim、全角斜杠归一；
只给了中类（「名词」）也认，十九个中类互不重名，唯一匹配是安全的。
**真的对不上才返回 null，不猜一个最像的。**
